# VKomado 1.1.0 セットアップ

Windows 11 x64用。配布物は `VKomado-1.1.0-Setup-win-x64.exe`。ARM64と32bit Windowsには対応しない。VC++ランタイムは静的リンクしており、利用者が開発ツールや.NETを追加する必要はない。

## 利用方法

1. セットアップEXEを実行し、Windowsの管理者確認を承認する。
2. スタートメニューの **VKomado** を開く。
3. **仮想画面をON** で有効化してビューアを開く。すでにONなら **ビューアを開く** を選ぶ。
4. **仮想画面をOFF** で対象画面のアプリをメインへ退避し、ビューアを閉じ、VDDデバイスを無効化する。
5. 不要になったら管理画面の **アンインストール**、またはWindowsの「インストールされているアプリ」から削除する。

管理画面の×ではVDDは有効のまま残る。ビューアの×ではウィンドウを退避してビューアだけを閉じる。退避できないウィンドウがある場合は停止・削除を中止する。

ON／OFF、導入・削除には管理者権限が必要。管理画面とビューアは通常権限で動く。再起動が必要な場合は表示し、自動再起動はしない。

[ウィンドウの移動](WINDOW-PICKER.md)、[ショートカット設定](SHORTCUTS.md)も参照。

## SharedVDからの更新

アンインストールは不要。SharedVDの管理画面・ビューア・ショートカット設定を閉じてからVKomadoのセットアップを実行する。スタートメニューとアプリ一覧はVKomadoになり、導入完了後に旧名のEXEとスタートメニュー項目を整理する。

インストーラーのAppId、`%ProgramFiles%\SharedVD`、`HKLM\SOFTWARE\SharedVD`、`%LOCALAPPDATA%\SharedVD` は互換性のため維持する。新規インストールも同じ内部パスを使用する。VDDの所有区分・設定ファイル・ショートカット設定を移動や初期化せず引き継ぐ。旧版と新版の同時起動防止用の内部識別子も維持する。

## 新規導入と既存VDDの扱い

| 検出した状態 | 処理 |
| --- | --- |
| VDDも既存設定もなし | 署名済みVDD 25.7.23を登録し、1080p60の仮想画面を1台作成 |
| VDDが1台存在 | 既存デバイスを再利用。既存ドライバー・設定は上書きしない |
| VDDが複数存在 | 対象を確定できないため導入を中止 |
| VDDはないが既存設定が残る | 設定を上書きせず導入を中止 |
| 前回の操作が未完了 | 再インストールを中止。アンインストールから残りの削除を再試行 |

新規導入には `config/vdd-distribution.xml` を使用する。特定のGPU製品名は指定せず、720p／1080p／1440p／4K・60Hzを登録する。解像度はWindowsのディスプレイ設定で変更できる。既存設定で候補が不足する場合は [解像度の追加手順](RESOLUTION-PRESETS.md) を参照。

新規ドライバーと設定ファイルは `%ProgramFiles%\SharedVD\Driver` に置き、VDDの `VDDPATH` 設定で参照させる。既存の `C:\VirtualDisplayDriver` は再利用時にも変更しない。

管理対象はPnPハードウェアIDで検出し、対象のインスタンスIDを導入記録へ保存する。物理GPUの一括無効化やドライバーの強制削除は行わない。

既存VDDを再利用した場合、そのVDDはVKomadoのアンインストール後も残る。削除対象は、このセットアップが新規作成したデバイスと新規登録したINF。パッケージを他デバイスが使用している場合は、強制削除せず復旧用ファイルと導入記録を残す。

## 構成とビルド

- `VKomado.Control.exe`: 管理画面。管理操作だけ別プロセスへ昇格する。
- `VKomado.Device.exe`: 検出・導入・ON／OFF・削除。SetupAPI／NewDevとWindows標準PnPUtilを使用する。
- `VKomado.Viewer.exe`: ビューア、ウィンドウ移動、終了時退避、ショートカット設定。
- `HKLM\SOFTWARE\SharedVD`: 対象デバイス、INF、所有区分、操作段階、導入先の記録。
- `packaging/VKomado.iss`: Inno Setupによるファイル導入・削除、アプリ一覧とショートカットの登録。

ビルド環境とコマンドは [README](../README.md#ソースからビルド) を参照。ドライバーは固定ZIPのSHA256、展開物との一致、署名をビルド時に検証する。管理ツールにもドライバー3ファイルのSHA256を埋め込み、導入前に照合する。VKomadoのEXE自体は未署名。

`manager_tests` は対象デバイスの識別、INF名、ドライバー改変の検出を検査し、レジストリや実デバイスを変更しない。`manager_ui_test` は自身が起動した管理画面のボタン、応答、正常終了を検査する。これらは新規PCへのドライバー導入や、再起動を伴う操作を検証するものではない。

## 復旧

`VKomado.Device.exe --inspect` は読み取り専用の診断。`phase=cleanup-required` または `uninstalling` の場合は、アプリ一覧からアンインストールを再実行する。デバイス削除後に再起動が必要な場合も、再起動後に同じ手順で残りを整理する。復旧完了前にインストール先フォルダーや導入記録を手動削除しない。

ユーザーごとの診断ログ `%LOCALAPPDATA%\SharedVD\Logs` はアンインストールで削除しない。不要になったら利用者が削除できる。強制終了・クラッシュ時のウィンドウ退避は対象外。
