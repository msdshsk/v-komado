# ウィンドウ移動

ビューア起動中に設定したキー（初期値Shift+F6）を押すと、メイン画面にサムネイル一覧を表示する。押した瞬間のカーソルの所属モニターで方向を固定し、その後カーソルを一覧へ移しても方向は変えない。

| カーソル位置 | 一覧の対象 | 移動先 |
| --- | --- | --- |
| 対象VDDの仮想画面 | その仮想画面上のウィンドウ | Windowsのプライマリ画面 |
| その他の画面 | 対象VDD以外の画面上のウィンドウ | 対象VDD |

クリック、矢印＋Enterで即座に移動する。移動が確認できたら一覧を閉じ、移動したアプリへフォーカスとカーソルを移す。Esc、キャンセル、再度選択キーを押すと取り消す。取り消し時に一覧が前面なら元のフォーカスとカーソル位置を復元する。別アプリに切り替えていた場合はフォーカスを奪わない。帰還キー（初期値F6）は一覧を閉じ、メイン画面中央へ帰還する。

一覧は6件ずつ表示する。前へ／次へ、ホイール、PageUp／PageDownで移動。更新ボタンまたはF5で再列挙する。ショートカット競合時は「表示」メニューに登録不可と表示し、メニューから開ける。表示メニューから開くときもカーソル位置が方向を決めるため、通常は「送る」になる。

## 実装

`app/window_picker.h/.cpp` が一覧と配置を担当し、既存のC++ビューアのUIスレッドから呼び出す。ビルドにはVKomadoのルート配下の `app` ディレクトリが必要。現行の改変済みビューアは `viewer/` に同梱する。パッチ適用は不要。

サムネイルには [DwmRegisterThumbnail](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmregisterthumbnail) を使う。表示中の最大6件だけを登録し、ページ移動・終了時に解除する。追加のWGCセッションや入力フックは作らない。最小化中・サムネイル取得不可の場合はタイトルと説明を表示する。保護コンテンツのプレビューは保証しない。

現在のWindowsデスクトップの表示中・最小化中のトップレベルウィンドウが対象。シェル、タスクバー、VKomado本体、通常のツールウィンドウ、非表示・cloakedウィンドウは除外する。所有元が表示されているダイアログは独立したカードにしない。

選択したウィンドウと、同じPID内でその所有関係をたどれる表示中のダイアログだけを移す。同じPIDの別の独立ウィンドウは対象外。移動前にHWND・PID・所属モニターを再確認する。作業領域へ収まる位置とサイズに調整し、通常ウィンドウとツールウィンドウの座標系の違いを扱う。最大化ウィンドウはいったん通常位置を移し、移動確認後に最大化を復元する。最小化ウィンドウは表示して移す。

[WINDOWPLACEMENT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement) の `WPF_ASYNCWINDOWPLACEMENT` で相手のUIスレッドを待たず配置を依頼し、タイマーで最大1.5秒検証する。拒否・消失・画面切断はエラーとして扱う。既に移動できたウィンドウは元に戻さない。管理者権限のアプリ、独自配置制御を行うアプリ、所有関係のない別プロセスのダイアログは手動移動が必要な場合がある。

## 検証

`tests/picker_regression.cpp` はテスト専用ウィンドウと、新規に起動したビューアだけを操作する。`--rescue-process-id` で一覧と退避の対象をテストPIDに限定し、`--keep-windows` でユーザーのウィンドウへの終了時操作を避ける。実際のShift+F6、双方への移動、ダイアログ追従、同一PIDの別窓の除外、Esc、最大化、最小化、移動拒否、閉じた候補、6件以上のページ切り替え、クリック、空一覧、F6との共存を検査する。

画面検証時だけ、同じ一覧コンポーネントをテストプロセス内で開き、そのテスト自身のウィンドウのキャプチャ除外を解除して撮影する。通常のビューア設定は変更しない。結果は `artifacts/picker-regression-results.txt`、画像は `artifacts/picker-ui.png`。異なるDPI同士の実機移動や、全アプリの権限・ダイアログ構成を網羅する試験ではない。
